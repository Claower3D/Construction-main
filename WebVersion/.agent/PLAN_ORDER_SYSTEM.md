### Файл 3: `index.html` — НУЖНО ОБНОВИТЬ

#### 3.1 Навигация — роль-зависимая видимость (Пункт 5)

**Текущее поведение:** "Мои заказы" видны всем ролям
**Нужное поведение:**

- **Заказчик** видит: "Мои заказы" (`showPage('orders')`)
- **Исполнитель** видит: "Лента заказов" + "Мои работы" (вкладки)
- "Мои заказы" в меню заказчика **скрыта** для исполнителя

**Изменения в навигации (orderer dropdown):**

- "Мои заказы" → остаётся как есть (orderer only)

**Изменения в навигации (contractor dropdown):**

- "Лента заказов" → остаётся как есть
- "Мои работы" → остаётся как есть

#### 3.2 Страница заказов — двойное поведение (Пункт 3, 4)

**Для роли ЗАКАЗЧИК (`orderer`):**

- Заголовок: "Мои заказы"
- Показывает ТОЛЬКО заказы с `customerId === 'self'`
- Скрывает вкладки исполнителя
- Показывает кнопку "Создать заказ"
- Статусы: открытый, в работе, завершён

**Для роли ИСПОЛНИТЕЛЬ (`contractor`):**

- Заголовок: "Лента заказов"
- Две вкладки:
  - **"🌐 Лента заказов"** — ВСЕ открытые заказы (status === 'open'), можно откликнуться
  - **"📌 Мои работы"** (новое!) — заказы, которые исполнитель взял на себя
- "Мои работы" показывает: заказы из `contractorWorks` localStorage
- Карточка работы: название, бюджет, статус, дата взятия, кнопки (завершить/отказаться)

#### 3.3 Логика откликов и взятия заказа

- Исполнитель нажимает "Откликнуться" → модалка с предложением
- После принятия → заказ попадает в "Мои работы"
- Статус заказа меняется на `in_progress`
- В "Мои заказы" заказчик видит обновлённый статус

## Ключевые решения

1. **Единое хранилище заказов** — `buildEstimateOrders` в localStorage (уже существует)
2. **Разделение по ролям** — `selectedRole` в localStorage определяет что видит пользователь
3. **"Мои работы"** — отдельный массив `contractorWorks` для отслеживания взятых заказов
4. **Статус-модель заказа**: `open` → `in_progress` → `completed`
5. **AI-корректировка** — regex-парсинг промптов на русском языке (без реального API)
